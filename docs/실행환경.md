# 실행환경 및 재현 범위

## 실측 환경

- Ubuntu 22.04.4 LTS, Linux x86_64.
- Python 3.12.4, venv + pip. Python 패키지의 실행 의존성은 `requirements.txt`에 버전 고정.
- NVIDIA RTX A6000 48GB 한 장. 개발 서버에는 여러 GPU가 있으나 개별 실행은 선택한 한 장을 사용.
- NVIDIA Driver 570.144, CUDA Toolkit 12.9 / nvcc V12.9.41.
- llama.cpp 커밋 `86b94708f22478f900b76ca02e316f4f3418faff`, Release, CUDA architecture 86.
- 운영 모델: Gemma 4 31B IT IQ4_NL, 비전 projector BF16.
- 생성 temperature 0, seed 42, 최대 4096 tokens. 슬롯별 문맥 24576, 2슬롯 합계 49152.
- 문서 갱신 최대 6144 tokens. 요청 timeout 240초, 서버 startup timeout 180초.
- 원본 이미지와 판단 요청은 로컬 llama.cpp의 `127.0.0.1` endpoint로 전달.

추론 환경을 작게 구성하기 위해 과거 연구용 환경 전체의 pip freeze를 사용하지 않고, 현재 실행 코드가 실제 사용하는 의존성과 그 하위 의존성의 설치 버전을 추출했다. 다른 실험용 OCR·학습 프레임워크는 설치할 필요가 없다.

## 설치·실행 순서

1. ZIP을 UTF-8 파일명을 지원하는 도구로 압축 해제한다.
2. Python 3.12, NVIDIA 드라이버, CUDA 12.9, Cairo·OpenGL·GLib·OpenSSL 시스템 라이브러리를 준비한다.
3. `bash scripts/setup.sh`로 `.venv`를 만든다.
4. GPU 실행 시 `python scripts/download_models.py`로 공개 가중치를 받고 `bash scripts/build_runtime.sh`로 런타임을 빌드한다.
5. `python scripts/smoke_test.py`로 데이터 및 설정을 점검한다.
6. README의 Train/Frozen CLI 또는 대시보드로 실행한다.

시스템에 Python 3.12가 없는 경우 설치 담당자가 Python 3.12 환경을 먼저 준비해야 한다. CUDA 빌드가 필요하면 `build-essential`, `cmake`, CUDA Toolkit과 개발용 라이브러리를 설치한 뒤 `bash scripts/build_runtime.sh`를 실행한다. `model/runtime/llama-server --version`으로 로더 오류를 확인할 수 있다. 빌드 스크립트는 현재 GPU에 맞춘 CUDA 아키텍처를 사용한다.

Notebook 도구는 `requirements-notebook.txt`로 별도 설치한다. Notebook은 먼저 저장 데이터와 실제 모델 출력을 CPU에서 검토하도록 구성했고, GPU 셀은 명시적으로 실행 스위치를 켜야 한다. 기본 Notebook 실행은 수천 건의 GPU 작업을 시작하지 않는다.

## 경로와 실행 기록

제출 사본의 모델 경로는 패키지 루트를 기준으로 계산한다. 실행 중에는 manifest에 해석된 절대 경로가 저장된다. 따라서 **실행을 새로 시작하기 전에** 패키지를 옮기는 것은 가능하지만, 진행 중인 실행 디렉터리를 다른 위치로 옮긴 뒤 그대로 재개하는 것은 지원하지 않는다.

추론 코드의 원본 대비 제출 변경은 경로 이식, 31B 배포 범위, 제출용 대시보드 정리다. 판정 엔진과 단계별 문서 자체는 보존했으며 파일 해시는 `source_manifest.json`에 기록했다. 별도 미검증 실험은 최종 파이프라인에 합치지 않았다.

## 평가 해석과 재현 한계

정답을 보는 Train 재판정은 문서 개발 절차다. Frozen 성능과 분리해야 한다. 공개 109건은 운영 기준 개발에 활용 가능한 자료이므로 독립 일반화 측정치로 볼 수 없다. GPU, llama.cpp 빌드, 입력 순서 및 모델의 수치 연산 차이로 결과가 일부 달라질 수 있다. 해시와 설정을 고정한 것은 실행 조건을 추적하기 위한 것이며 모든 하드웨어에서 비트 단위 출력을 보장한다는 뜻은 아니다.
