# AI 활용범위와 참가자의 주요 검토 과정

## 활용 도구와 범위

| 도구 | 활용 단계 | 주요 활용 |
|---|---|---|
| 로컬 Gemma 4 31B IT · IQ4_NL | 품질 판정, 피드백 생성, 가이드라인 갱신, 재판정 | 이미지·문맥 해석, 단계별 JSON 결과, 사례 기반 판단 기준 생성 |
| OpenAI Codex · GPT-6 Astra 기반 개발 지원 | 문제 분석, 구현, 테스트, 실험 분석, 문서 작성 | 코드 초안과 수정 제안, 로그·오류 분석, 반복 패턴 정리, 실행·평가 도구 및 문서 작성 지원 |

제출된 판정 파이프라인은 Gemma 로컬 추론으로 실행한다. Codex는 개발 지원 도구이며 심사 실행에 Codex 계정이나 외부 상용 AI API 인증정보가 필요하지 않다.

## 참가자의 주요 기여

참가자는 7범주를 한 번에 선택하는 방식 대신 이진·후보·최종 선택으로 나누는 구조를 결정했다. 실패한 단계에서 판단 기준을 문서로 축적하고, 실제 사용에서는 고정 문서로 재검토 필요성을 판단하도록 Train/Frozen 역할을 정했다. 후보 평가를 F1이 아니라 정답 포함률로 측정하고, 후보 집합을 넓게 유지하도록 요구했다.

참가자는 실제 이미지·alt·문맥과 판정 근거를 대시보드로 확인하며, 반복적으로 나타나는 오류와 개별 사례를 구분했다. 성능이 좋아진 수만 아니라 정답이 오답으로 바뀌는 부작용을 함께 확인하고, 문구·규칙·분기의 채택, 수정, 롤백을 결정했다. 공식 기준 개정에 따라 데이터와 프롬프트를 동기화하고, 공개 경계 사례의 데이터셋 라벨과 재검토 의견을 구분했다.

## 검토한 대안과 제외 이유

| 대안 | 관찰·우려 | 최종 결정 |
|---|---|---|
| 모든 사례에 무조건 피드백·재판정 | 맞는 판정까지 뒤집는 부작용과 추가 호출 비용 | Frozen에서 재검토 필요성을 먼저 판단 |
| 적절 판정에 추가 3차 재검산 | 교정과 악화가 함께 나타나 일관된 이득 부족 | 핵심 운영 단계에서 제외 |
| 읽을 수 있는 링크 문구 + 빈 alt를 항상 적절 처리 | 공식 기준 개정 후 이미지 고유 정보 누락을 놓침 | 이미지·문맥 예외 검사 추가 |
| 후보 재검토에서 후보 축소 | 실제 정답 후보를 제거할 가능성 | 기존·추가 후보의 합집합 사용 |
| 최종 유형을 후보의 우선순위만으로 선택 | 넓게 뽑은 잠정 후보를 확정 오류처럼 취급 | 원본과 후보별 근거 비교 유지 |
| 단일 사례만 위한 세부 문구 추가 | 다른 유형의 오탐과 과잉 적합 위험 | 반복 패턴을 검토하고 넓은 범위에서 회귀 비교 |

## 최종 선택 이유

가중치 재학습 없이도 실패 경험을 문서로 남기고 검토할 수 있으며, 새 기준과 기존 기준의 차이를 사람이 직접 확인할 수 있다. 세 단계의 실패 원인을 분리하고, 고정 가이드라인 버전·입력·피드백·재판정 기록을 연결하여 운영과 개선을 구분한다. 이는 무조건 더 많은 호출을 하는 것보다 검토 가능성과 유지보수 측면에서 적합하다고 판단했다.

개발 과정의 반복 비교는 독립 K-fold 교차검증과 구분한다. 공개 Train 및 공개 경계 사례를 개선에 활용했으므로 해당 자료에 대한 성능만으로 새로운 데이터의 일반화가 입증되었다고 해석하지 않는다.
