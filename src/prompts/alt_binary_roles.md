[Instruction]
원본 이미지와 웹 문맥으로 이미지의 역할을 먼저 판단하라. 그 역할에서 필요한 정보를 정하고,
alt_text와 주변 문맥이 해당 기준을 충족하는지 확인한 뒤 "적절" 또는 "부적절"로 판정하라.
이 단계에서는 오류 유형을 분류하지 않는다.

[설명]
파이프라인 입력:
- image: 원본 이미지.

메타데이터 정의 (학습 데이터 README 데이터 사전):
- alt_text: 원본 대체텍스트 (원문 그대로). 빈 문자열 포함.
- page_title: 수집 페이지 제목.
- context_text: 이미지 인접 텍스트. 최대 500자.
- in_link: 링크·버튼 내부 여부. true, false.
- link_dest: 링크의 표시 텍스트. in_link=true일 때.
- heading_path: 문서 내 헤딩 경로.
- kogl_marker: 수집 페이지의 공공누리 표시 여부. true, false.

[판정 기준]
다음은 공식 라벨링 가이드라인 v0.9의 역할·경계 기준을 이진 판정용으로 정리한 것이다.

1. 역할 선택
image_roles에는 "정보 전달", "기능 전달", "텍스트 전달", "자료 식별", "장식" 중
해당하는 역할을 선택한다. 한 이미지가 여러 역할을 수행하면 함께 선택한다.
"자료 식별"은 책자 표지 등 특정 자료를 구분하는 역할을 나타내는 작업용 표현이다.
이미지 모양만으로 역할을 정하지 말고 링크 여부와 주변 문맥을 함께 확인한다.

2. 역할별 충족 기준
- 정보 전달: 사진이 전달하는 주요 대상·행동·장면, 차트·도표의 핵심 수치나 결론이 전달되어야 한다.
  링크 안의 촬영 사진 썸네일도 사진 자체의 정보를 확인한다. 행사명이나 기사 제목이 관련 있다는
  이유만으로 충족 처리하지 않는다. 사진의 주요 장면이 전달되는지 확인한다.
  인접 본문이 같은 내용을 충분히 서술하면 요약 수준의 alt도 인정한다.
- 기능 전달: 링크·버튼의 목적지 또는 동작 대상이 전달되어야 한다.
  같은 링크에 목적지를 알리는 텍스트가 이미 있으면, 이미지가 더하는 정보가 있는지도 확인한다.
  링크 안이라는 이유로 사진의 장면이나 안내 포스터의 본문 정보를 모두 생략해도 된다고 판단하지 않는다.
- 텍스트 전달: 포스터·카드뉴스·안내 배너는 해당 안내에 필요한 기간·대상·장소·방법·수치 등
  실제로 담긴 핵심 정보를 확인한다. alt나 주변 문맥에 제목만 있고 필요한 내용이 빠지면 미충족이다.
  전문이 길면 핵심 문구와 상세 설명 위치 안내도 인정한다. 모든 작은 글자를 나열할 필요는 없다.
- 자료 식별: 책자명·발행호 등 해당 문맥에서 자료를 구분하는 데 필요한 정보가 전달되는지 확인한다.
  표지에 글자가 있다는 이유만으로 모든 장식 문구와 표지 사진을 반드시 설명하도록 요구하지 않는다.
- 장식: 제거해도 정보 손실이 없는 순수 장식은 빈 alt가 충족이다.
  로고·아이콘이라는 외형만으로 장식으로 단정하지 않는다. 식별·기능·추가 정보가 있는지 확인한다.

3. 공통 확인
- alt와 이미지 내용이 맞는지, 파일명이나 내용 없는 표현만으로 필요한 정보를 대신하지 않았는지 확인한다.
- 인접 캡션이나 링크 문구를 그대로 반복하면서 추가하는 정보가 전혀 없으면 미충족이다.
  문맥과 문장이 일치한다는 사실 자체를 적절의 근거로 사용하지 않는다.
- 제목만 반복한 사진·포스터는 이미지 고유 정보가 전달되는지를 확인한다.
- 빈 alt 썸네일은 링크 텍스트가 목적지를 전달하고 이미지에 별도로 전달할 핵심 정보가 없으면 인정한다.
- 글자 수·표현의 자연스러움·오탈자 자체가 아니라 해당 문맥에서 필요한 정보의 전달 여부를 평가한다.

[Rule]
1. image_roles와 이미지 관찰 근거를 먼저 작성한다. alt의 주장을 그대로 이미지 관찰로 옮기지 않는다.
2. criteria_checks에는 이 이미지에 적용되는 핵심 기준을 1~6개 작성한다. 각 criterion은 필요한 정보나
   기능을 구체적으로 명시한다. alt_evidence에는 alt가 실제 전달한 내용을, context_evidence에는
   주변 문맥이 실제 보완한 내용을 짧게 쓰고, 근거가 없으면 "없음"이라고 쓴다.
3. 각 기준의 status는 "충족", "미충족", "확인불가" 중 하나다. 미충족이면 해당 근거에 빠진 핵심 정보를
   구체적으로 쓴다. 관찰할 수 없는 내용을 만들어내지 않는다.
4. 적용 기준을 모두 충족하면 verdict는 "적절", 하나라도 미충족이면 "부적절"이다.
   확인불가를 자동으로 충족 또는 미충족으로 바꾸지 말고, 확보한 근거로 최종 판정하고 한계를 reason에 쓴다.
5. 각 문자열은 한국어 350자 이내로 짧게 쓴다. reason은 기준 검사 결과를 요약한다.
6. 아래 필드 순서대로 JSON 객체 하나만 반환하고 verdict는 마지막에 쓴다. 정답 라벨을 추측하지 않는다.

[Output format]
{"image_roles":["기능 전달"],"image_evidence":"돋보기 아이콘","criteria_checks":[{"criterion":"검색 기능을 알 수 있는가","alt_evidence":"alt가 검색이라고 설명함","context_evidence":"검색 입력창 옆 버튼","status":"충족"}],"context_evidence":"검색 버튼으로 사용됨","reason":"검색 동작을 전달함","verdict":"적절"}
또 다른 형식 예시:
{"image_roles":["텍스트 전달","기능 전달"],"image_evidence":"신청 기간과 대상이 적힌 안내 포스터","criteria_checks":[{"criterion":"신청 기간과 대상이 전달되는가","alt_evidence":"신청 안내라는 제목만 있어 기간과 대상 누락","context_evidence":"인접 문구에도 제목만 있음","status":"미충족"}],"context_evidence":"신청 안내 링크의 포스터","reason":"신청에 필요한 기간과 대상이 전달되지 않음","verdict":"부적절"}
예시는 출력 형식이다. 실제 입력의 관찰 근거로 바꾸고 해당하는 객체 하나만 출력한다.
