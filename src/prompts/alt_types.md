[Instruction]
원본 이미지, alt_text, 웹 문맥을 대조하여 아래 여섯 오류 유형 중 실제로 해당하는 유형을 모두 선택하라. 각 유형의 정의를 충족하는 구체적 근거를 제시한다. 입력은 앞선 검토에서 정보 전달 문제가 발견된 사례다. 이 단계는 오류 유형의 복수 선택만 수행한다.

[설명]
파이프라인 입력:
- image: 원본 이미지.

메타데이터 정의 (학습 데이터 README 데이터 사전):
- alt_text: 원본 대체텍스트 (원문 그대로). 빈 문자열 포함.
- page_title: 수집 페이지 제목.
- context_text: 이미지 인접 텍스트. 최대 500자.
- in_link: 링크·버튼 내부 여부. true, false.
- link_dest: 링크의 표시 텍스트. in_link=true일 때.
- heading_path: 문서 내 헤딩 경로.
- kogl_marker: 수집 페이지의 공공누리 표시 여부. true, false.

유형 정의와 예시 (KoAltQ 가이드라인 v0.9 2절):
- 무의미형: 내용 없는 상투어·기호 나열. 예: 행사 안내 배너 → "이미지", "사진", "*", "배너".
- 파일명형: 파일명·경로·확장자 그대로. 예: 조직도 → "org_chart_v2.png".
- 중복형: 인접 텍스트(캡션·제목·링크 문구)를 그대로 반복해 정보가 0. 예: 캡션 "2026 예산 개요" 바로 위 차트 → "2026 예산 개요".
- 장식오용형: 순수 장식 이미지에 내용성 alt를 부여 (`alt=""`가 정답인 경우). 예: 구분선 그래픽 → "아름다운 구분선".
- 불충분형: 방향은 맞으나 핵심 정보 누락. 예: 3단계 신청 절차 안내도 → "신청 절차".
- 무관형: 이미지 내용과 불일치. 예: 오시는 길 지도 → "회사 로고".

[Rule]
1. matched_types에는 정의에 해당하는 유형을 하나 이상 선택하고 유형별 근거를 쓴다. 여러 유형을 선택할 수 있으며 같은 유형은 중복 선택하지 않는다.
2. reason에는 종합 근거, image_evidence에는 이미지 근거, context_evidence에는 문맥 근거를 쓴다. 유형별 근거를 포함해 각 근거는 한국어 350자 이내로 쓴다.
3. 아래 형식의 JSON 객체 하나만 반환한다. 최종 단일 라벨은 선택하지 않는다.

[Output format]
{"matched_types":[{"label":"불충분형","reason":"해당 유형을 선택한 근거"}],"reason":"종합 근거","image_evidence":"이미지에서 확인한 내용","context_evidence":"문맥에서 확인한 내용"}
여러 유형이 실제로 해당하면 matched_types에 유형별 객체를 추가한다. 예시는 형식 설명이며 실제 입력의 근거로 바꾼다.
